# Architecture

    host
     ├─ .cellwall/config.yaml, policy.yaml     your decisions (committed)
     ├─ .devcontainer/                         generated by `cellwall init` (committed)
     └─ .cellwall/state/                       written by `cellwall prepare` (gitignored)
          policy/policy.json  audit/  compose.override.yaml  compose.env  manifest.json

    docker
     ├─ network `sandbox`  internal + gateway_mode_ipv4=isolated   (ADR 0001)
     │     agent ──HTTP(S)_PROXY──▶ gateway:3128
     └─ network `egress`   normal bridge
           gateway ──▶ internet   (only for connections the policy allows)

- **agent**: your toolchain image, non-root, all capabilities dropped, on the sandbox network only.
  Workspace is bind-mounted; protected paths are read-only mounts; secrets appear as files under
  `/run/secrets`.
- **gateway**: the `cellwall` binary in a `FROM scratch` image. Matches the policy on the *name*,
  vets the resolved address, writes the audit record, then dials the vetted IP (ADR 0004/0005).
- **Flow of a change**: edit `.cellwall/config.yaml` / `policy.yaml` → `cellwall prepare` rewrites
  `state/policy/policy.json` atomically → the gateway hot-reloads by content hash and keeps the
  last good policy if the new one is invalid. Container-shaped changes (image, mounts) need
  `cellwall init` and a restart.

See `threat-model.md` for what this does and does not protect, and `spikes.md` for the evidence.
